## Recovery changes

- One valid healthy sample confirms recovery by default (threshold 0.93).
- A dedicated SimSpeed recovery alert appears when CPU, memory, or estimated grid pressure keeps the overall incident open.
- Recovery notifications bypass the incident-start cooldown and require enabled Discord delivery and recovery alerts.
- Missing or invalid speed observations cannot confirm recovery.
- Manual and timer sampling share overlap protection. Storage failures no longer prevent recovery evaluation.

## Install and configure

Back up the installed plugin and config, stop the server, replace the plugin ZIP in the Torch plugins folder, and restart. Retain your webhook credentials privately.

For an existing config, set `SimulationRecoverySamples` to `1` and `SimulationRecoveryThreshold` to `0.93`; enable `DiscordRecoveryAlertsEnabled` if Discord recovery notifications are wanted. Reload with `!profilerplusadmin reload` after editing a running installation. The packaged example config matches this candidate; the root repository example remains the earlier documented version.

With a 10-second interval, confirmation normally occurs at the next completed sample, plus processing and delivery time. This plugin does not automatically reduce game workload or guarantee actual speed recovery. Test on a controlled server before production deployment.
